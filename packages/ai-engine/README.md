# @helios/ai-engine

Local AI copilot orchestration, local Ollama LLM provider abstraction, targeted context extraction, secret sanitization, and authoritative AST ground-truth validation for HELIOS.

---

## 1. Core Architectural Principle: Strict Separation of Determinism and Heuristics

1. **Deterministic Engines are the Source of Truth:**
   - Security audits (`@helios/security-engine`)
   - Schema and specification validation (`@helios/validator`)
   - Compliance mappings and risk scoring (`@helios/compliance-engine`)
   - Semantic API diffing and breaking change analysis (`@helios/diff-engine`)
   - Canonical AST representations (`@helios/canonical-ast`)

   The AI copilot **NEVER** invents findings, alters severity scores, reclassifies breaking changes, or certifies compliance.

2. **The Copilot is an Explanatory and Advisory Layer:**
   When an engineer requests narrative explanations of vulnerabilities, endpoint summaries, breaking change breakdowns, or remediation advice, the local AI copilot synthesizes clear human-readable explanations based solely on targeted deterministic context.

3. **Untrusted LLM Output & AST Ground-Truth Validation:**
   LLM output is treated as untrusted user input. Every reference generated by the model (endpoints, schemas, findings, compliance controls, diff changes) is cross-checked against the authoritative Canonical AST and engine outputs by the `AstGroundTruthValidator`. Any hallucinated or improperly associated entities are flagged, redacted, or cause the answer to be rejected.

## 2. Architecture & Data Flow

```
+-----------------------------------------------------------------------+
| User Query & Analysis Targets (Endpoint, Finding, Diff, Compliance)   |
+-----------------------------------------------------------------------+
                                  │
                                  ▼
                     [ContextBuilder.buildContext]
   - Filters only relevant endpoints, schemas, findings, diffs
   - Sanitizes sensitive tokens, passwords, keys, secrets
   - Formats compact, targeted context (no full-AST dumps)
                                  │
                                  ▼
                    [formatContextPrompt (V1)]
   - Combines versioned system instructions & structured JSON schema
                                  │
                                  ▼
                         [LlmProvider]
   - OllamaProvider (local http://localhost:11434, zero external APIs)
   - MockLlmProvider (deterministic offline testing)
                                  │
                                  ▼
                         [parseAiResponse]
   - Extracts JSON from raw text or markdown code fences
   - Fallback parser prevents fatal crashes on malformed LLM responses
                                  │
                                  ▼
                   [AstGroundTruthValidator.verify]
   - Verifies referenced endpoints exist in Canonical AST
   - Verifies referenced schemas exist in Canonical AST
   - Verifies referenced findings exist in deterministic finding results
   - Verifies finding-to-endpoint associations
   - Verifies referenced compliance controls exist in framework mappings
   - Verifies referenced diff changes exist in diff report
                                  │
                                  ▼
                   [VerifiedAiAnswer Output]
   - Status: 'verified' | 'partially_verified' | 'rejected'
   - Original and verified narrative text
   - List of valid references & detected hallucinations
   - Remediation advisory notes & verification timestamp
```

## 3. Ollama Provider Configuration

The copilot connects to a locally hosted Ollama daemon by default:

```typescript
import { AiCopilot, OllamaProvider } from '@helios/ai-engine';

const copilot = new AiCopilot({
  ollamaConfig: {
    baseUrl: 'http://localhost:11434', // Default
    modelName: 'llama3',               // Default: 'llama3' (or mistral, codellama, qwen)
    timeoutMs: 30000,                  // Default: 30s timeout with AbortController
    temperature: 0.1,                  // Default: 0.1 for high determinism
  },
});
```

For offline or CI environments without Ollama running, use `MockLlmProvider`:

```typescript
import { AiCopilot, MockLlmProvider } from '@helios/ai-engine';

const mockProvider = new MockLlmProvider();
mockProvider.setResponse({
  answer: 'The endpoint requires HTTP Bearer token authentication.',
  referencedEndpoints: ['get:/users/{id}'],
  referencedSchemas: ['User'],
  referencedFindings: ['AUTH-001:get:/users/{id}'],
  referencedControls: ['PCI-4.2.1'],
  referencedChanges: [],
  limitations: ['Static analysis only'],
  confidence: 'HIGH',
});

const copilot = new AiCopilot({ provider: mockProvider });
```

## 5. Ground-Truth Validation Checks

The `AstGroundTruthValidator` performs rigorous structural checks:

| Violation Type | Trigger Condition | Consequence |
|---|---|---|
| `NONEXISTENT_ENDPOINT` | Referenced endpoint ID or path does not exist in Canonical AST | Flagged in `hallucinationsDetected`, stripped from `validReferences.endpoints` |
| `NONEXISTENT_SCHEMA` | Referenced schema name does not exist in AST `schemas` | Flagged in `hallucinationsDetected`, stripped from `validReferences.schemas` |
| `NONEXISTENT_FINDING` | Referenced finding ID is not in the deterministic security or validation findings | Flagged in `hallucinationsDetected`, stripped from `validReferences.findings` |
| `UNASSOCIATED_FINDING` | Referenced finding exists, but does not belong to the referenced endpoint | Flagged in `hallucinationsDetected`, warning emitted |
| `NONEXISTENT_CONTROL` | Referenced compliance control is not present in compliance mappings | Flagged in `hallucinationsDetected`, stripped from `validReferences.controls` |
| `NONEXISTENT_DIFF_CHANGE` | Referenced diff change is not present in the semantic diff results | Flagged in `hallucinationsDetected`, stripped from `validReferences.changes` |

### Status Resolution:
- **`verified`**: All referenced entities were confirmed to exist in the ground truth.
- **`partially_verified`**: At least one reference was confirmed, but hallucinations or unassociated findings were detected. Remediation advisory notes are appended.
- **`rejected`**: All claimed references were hallucinations, or critical fabrications were detected.

## 6. Privacy & Security Protections

1. **No External Network Calls:** The engine operates 100% locally. Ollama communicates over loopback (`localhost:11434`).
2. **Context Sanitization:** Sensitive keywords (passwords, tokens, secret keys, authorization headers) in parameter examples, headers, or schema samples are scrubbed (`[REDACTED_SECRET]`) prior to sending context to the LLM.
3. **No Shell or Code Execution:** The copilot exclusively produces text explanations; it never executes code, scripts, or shell commands suggested in LLM outputs.

## 7. Testing Strategy

Run unit tests:
```bash
pnpm --filter @helios/ai-engine test
```

- **Unit tests (19 tests):** Completely offline and deterministic using `MockLlmProvider` and targeted input vectors.
- **Integration tests (2 tests):** Automatically detect whether a live Ollama daemon is reachable at `http://localhost:11434`. If unavailable, tests gracefully skip (`t.skip()`) so CI pipelines remain 100% stable and fast.
